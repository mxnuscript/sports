# Edge

A dependency-free sports betting research workspace. Requires Node.js 24.5 or newer (uses Node’s environment-proxy support).

Run `npm start` from `/workspace/sports` (default port 3000; override with `PORT`). Run `npm test` for payout math tests.

Includes a filterable, explicitly illustrative odds board, two-outcome arbitrage allocation, and bonus-bet conversion with cash hedge modeling. Multi-book moneylines, spreads, and totals use The Odds API for NBA, NFL, and MLB. Player props load on demand through the event-level API. No automated wagers, accounts, or persisted bankroll data are connected. Calculators assume exhaustive outcomes and matching settlement rules; fees, voids, pushes, stake rounding, and promo restrictions require independent verification.

## Live odds setup

Create an account at https://the-odds-api.com/ and obtain a key with the required sports/markets entitlement. Enter it securely as `ODDS_API_KEY` in environment settings, with destination `api.the-odds-api.com`. Do not place keys in browser code, Git, or chat. Save the settings and restart `npm start` after the binding is available. In cloud environments preserve the provided proxy and CA trust.

The board starts in live mode; choose one sport and refresh manually. Each sport request includes moneylines, spreads, and totals; provider quota costs depend on your plan. Server responses are cached for 60 seconds and concurrent requests are combined. No background polling occurs. Provider market timestamps are shown and prices older than five minutes are marked stale. The fetched timestamp is not a guarantee of price freshness or availability at the sportsbook. Demo mode must be selected explicitly; live failures never substitute demo data.

`GET /api/odds?sport=NBA` (also NFL and MLB) returns normalized sportsbook rows or a sanitized error. No key returns 503. Missing seasonal coverage may return an empty array. Player props use the separate on-demand event-level endpoint described below. API tests use synthetic provider fixtures; authenticated provider access must be verified after the key and network settings are applied.

True value estimates require a calibrated probability model or justified market reference; implied probability alone is not an edge.

## Hosting and comparisons

See [DEPLOY.md](DEPLOY.md) for the Render Blueprint, private sign-in, and deployment verification. The board defaults to DraftKings and can filter other available books. ## Oregon and the compact board

The board combines both teams' moneylines and spreads on one row per game and sportsbook. Alternate spread lines are retained; totals and props stay separate. Oregon mode defaults to DraftKings plus user-reported ReBet when explicitly loaded. DraftKings is confirmed on the Oregon Lottery sports page on October 29, 2026: https://www.oregonlottery.org/sports/. This is coverage verification, not an exhaustive legal review. Other supplied sportsbook prices remain visible in explicit reference mode and are not represented as executable from Oregon.

The Oregon platforms tab records Underdog, Betr, PrizePicks and ReBet access as reported by the user. Underdog/PrizePicks have indicative prop-feed connectors; ReBet has sportsbook-format connectors; Betr is manual-only because it is absent from the supplied provider coverage list. Account/product availability is not independently verified by a price feed. A manual pick’em watchlist records user-confirmed eligible selections in browser localStorage (maximum 100). It does not calculate arbitrage from pick’em selections, store account credentials, or invent prices. Check exact product, state eligibility, payouts, void rules and entry terms directly in your account. This directory is a starting point; it does not claim to enumerate every Oregon retail, tribal or fantasy offering.

### Windows quick start / update

Download the latest ZIP for `edge/live-odds-workspace` and extract it to a new folder. Stop the old app with Ctrl+C. Double-click `start-windows.cmd` in the folder containing package.json, enter your Odds API key when prompted, and open http://localhost:3000. Requires Node 24.5 or newer. The launcher keeps the key only in the process environment and avoids PowerShell's npm.ps1 execution-policy issue. It does not change execution policy or install dependencies. Existing browser watchlist notes remain on the same localhost port/browser. To update, download/extract the new ZIP; changes pushed to GitHub do not update an existing ZIP extraction automatically.

## Comparison tools

Switch between the compact team view and Compare books. Comparison columns group identical event, selection, market and line; different spreads/totals are never treated as the same price. Best shown excludes quotes older than five minutes or with unknown timestamps in provider mode, and means only best among displayed prices. It does not imply positive EV or Oregon access. Click any quote to inspect its timestamp and transfer odds into a calculator.

Pregame filtering is on by default, with start-time/name sorting and CSV export of filtered quotes. CSV formula-leading fields are escaped. Odds movement indicators compare the last loaded provider snapshot; there is no historical price database. Auto-refresh is off by default, configurable at 60/120/300 seconds, pauses in hidden tabs, and consumes provider credits after cache expiry. Quotes still use the server's 60-second cache; this is not a real-time streaming feed.

The arbitrage reference table supports total stake, minimum return and market filters. Stakes are rounded to cents and the lower of the two modeled settlement profits is reported. Actual minimum stakes, limits, fees, voids and settlement still need verification. Oregon mode continues to suppress cross-book actionable candidates because only DraftKings coverage is confirmed.

Design references: AVO's public odds-screen page (https://www.avo.bet/product/odds) informed side-by-side comparisons, search and market navigation. OddsJam's supplied arbitrage page could not be inspected because it returned HTTP 403. No proprietary assets, pricing feed or real-time claims are copied from these products.

## Ask AI (optional)

Ask AI supports Google AI Studio's Gemini API and the OpenAI Responses API. It requires a separate `EDGE_AI_KEY` on the server. Set `EDGE_AI_PROVIDER=gemini` for a Google key or `openai` for OpenAI (default). Gemini discovers available Flash text models using the authenticated model catalog, preferring stable Flash, then Flash Lite, then Flash preview; it never automatically selects Pro, image or audio models. The available model catalog is cached for two minutes; Check connection / load models forces a refresh. Catalog listing does not guarantee generation quota or structured-output support. OpenAI defaults to `gpt-5-mini`. Set `EDGE_AI_MODEL` to an available compatible model if needed. OpenAI API billing is separate from a ChatGPT subscription. Obtain a key from https://platform.openai.com/api-keys and set a spending budget in your API account. Never put keys in the browser, repository or chat. The Windows launcher asks you to choose G for Google AI Studio, O for OpenAI, or Enter to skip AI, then prompts for the chosen provider key privately. Get a Google key at https://aistudio.google.com/apikey. Gemini free-tier access depends on model, project, region and quota; check Google’s current billing and data-use terms. A Google AI subscription does not necessarily cover API usage. Keys are not persisted by the launcher. Existing manual npm users can set EDGE_AI_KEY in the current process using the same secure Read-Host pattern used for ODDS_API_KEY, then restart the server.

Each explicit question sends your question (maximum 2500 characters) and all eligible fresh pregame DraftKings quotes for the selected sport plus sourced matchup research when enabled to the selected provider. No chat history, other-book reference data, watchlist or account credentials are sent. For OpenAI, API storage is requested off (`store:false`). Gemini uses its native generateContent endpoint with header authentication. Each provider’s retention and data-use policies apply. No request is made automatically, and empty eligible snapshots skip the model call. A global 15-second cooldown and one in-flight request bound accidental usage; there is no persistent dollar-budget enforcement in the app.

The server validates structured output against supplied quote IDs, rejects unsupported legs, expired prices and same-event parlays, and computes illustrative parlay payouts itself. Multiplying leg prices does not establish an offered DraftKings parlay price or account for correlation, voids or limits. Break-even probability is price-derived, not a prediction. ESPN-reported injury and historical data are connected, but no calibrated true-probability model is available; live props enter AI context only when explicitly selected; the assistant cannot establish positive EV or guarantee profitable bets. Model reasoning is unverified research commentary. Prices must be checked again in the operator's app.

`POST /api/ask` accepts JSON with `message` and `sport` (NBA/NFL/MLB). Missing AI credentials return 503, invalid inputs 400, and cooldown/provider rate limits 429. Tests use mocked AI responses and synthetic odds. Authenticated provider access has not been verified without a configured API key. Server errors never return raw provider payloads or credential-bearing request errors.

### Gemini troubleshooting

Update to the latest ZIP if you see only “AI provider is unavailable.” Gemini now uses native `responseSchema` with unsupported JSON-schema fields removed. Errors show safe provider HTTP status and a classified reason instead of raw response bodies. HTTP 400 may indicate request settings; HTTP 404 indicates an unavailable model; HTTP 401/403 indicates key/project restrictions; HTTP 429 indicates quota; HTTP 5xx indicates provider failures. These classifications narrow diagnosis but are not authenticated end-to-end verification. If the model is unavailable, set EDGE_AI_MODEL to a compatible model shown in your Google AI Studio project and restart the server. Do not share keys, headers or raw credential-bearing logs.

Gemini HTTP 404 for the old hardcoded default is addressed by automatic model discovery. Download the latest version and restart; no key replacement is implied by a model-not-found error. An explicit EDGE_AI_MODEL overrides discovery, so remove an obsolete override if you previously set one.

### Persistent Gemini 503

Use Ask AI → Check connection / load models. This only reads the model catalog; it does not request an answer or test generation quotas. Errors identify Model discovery versus Answer generation (model name). If discovery succeeds and generation fails, choose another catalog-listed Flash model in the Gemini model selector (Flash Lite if available) and submit manually. This may incur normal generation charges. No automated retries or hidden fallback generations are performed. An explicitly selected UI model must be in the authenticated catalog; unknown models are rejected before generation. Persistent failures across listed models require checking the Google project/provider, not repeated application retries.

## Live player props and game rows

The default game view groups BOTH teams into a single table row per event/book, with aligned moneyline/spread prices, totals, and a View props action. Exact-line multi-book comparison remains available. Player props have their own compact table, pairing Over and Under for each player/line.

From the live board choose a sport, then View props on a game (or open Player props). Select an upcoming event and one market, then Load player props. Supported configured markets: NBA points/rebounds/assists/threes; NFL passing/rushing/receiving yards/receptions; MLB hits/total bases/pitcher strikeouts. Actual coverage and release times vary by event and subscription. This is an on-demand integration, not a claim that every market is offered.

`GET /api/props?sport=NBA&event=<provider-event-id>&market=player_points` uses the existing ODDS_API_KEY and platform-selected event odds endpoint (default DraftKings). Events must be upcoming and present in the current board snapshot. Requests are cached/coalesced for 60 seconds with a bounded 50-entry prop cache. One market/event is loaded at a time to control provider credits. Props are not polled in the background. Live NBA player-points retrieval was verified during development with 20 returned quotes. NFL/MLB prop mappings are configured but were not authenticated end-to-end checked in this change.

To include props in Ask AI, load a market, choose the matching AI sport, and check Include loaded prop event / market. The server retrieves/revalidates those quotes itself; an expired cache may consume credits. AI IDs retain player/stat/side/line identity. Same-event parlays remain unsupported; no fabricated correlated parlay prices or injury/lineup claims are introduced.

## Matchup research for Ask AI

Ask AI now enables sourced matchup research by default. ESPN public site/API feeds provide matched game summaries, home/away and overall records, season offense/defense statistics where supplied, last-five results and scoring averages, reported injuries with report dates, completed season-series meetings, and player season/recent-game statistics. Select one game or research every upcoming game returned for the selected sport. Player lookup covers the supplied athletes from loaded prop markets for each game using exact normalized roster identities; otherwise selected team leaders are loaded. Recent prop Over/Under/Push counts and means are computed from actual available game stats; missing values are excluded, never zero-filled. Counts are historical samples, not probability forecasts.

Preview matchup research fetches data without an AI generation request. No new research-provider key is needed. Existing odds/prop calls may consume odds-provider credits. When asking AI, enabled research is sent alongside the question and quotes, so AI token usage may increase. Research cache/coalescing uses a five-minute TTL, 1,000-entry cache cap, four concurrent source requests, ten-second per-request timeouts, and a 120-second total source-fetch deadline. Unofficial public endpoints have no stability/completeness guarantee. Windows/local access can differ from cloud access.

Only uniquely matched team pairs within 90 minutes of provider start time are joined; games underway/completed in source data are rejected. Unmatched games and source failures remain visible. With research enabled, the AI sees only odds from matched games; if no matches exist, it skips AI generation rather than inventing context. Explicitly disable research to request an odds-only illustration. Confirmed game-day inactive lists, official lineups, minutes projections, opponent-adjusted/defensive-versus-position metrics, and calibrated win probabilities are NOT supplied. A reported Out player prop is rejected if the AI selects it. Third-party injury status and old reports are never upgraded to confirmed inactives, and no injury entry never proves healthy.

Source retrieval timestamps differ from report/update times; injury reports older than 24h or undated are marked for rechecking. Player season-year is explicitly unknown when omitted by the provider. Historical samples may include preseason/prior-season results when source season types are unspecified. Do not interpret small-sample averages as causal injury effects or positive EV.

`POST /api/research` accepts JSON `{sport, eventId?, propEvent?, propMarket?}`. `POST /api/ask` adds optional `research` (default true) and `researchEvent`. Sources are linked in the UI. Live NBA validation matched Cavaliers–Hawks, fetched both teams' records/season stats, five recent results per team, two reported injury entries, and six player overviews via 11 source URLs. NFL/MLB paths are configured with the same best-effort coverage checks but were not live-validated in this change. AI payload/Out-player rejection tests use mocked model output; no authenticated Google generation was run in the cloud without an AI key.

## Full-slate workflow and interactive odds

Research no longer truncates after four games, six players or 80 quotes. All fresh pregame DraftKings quotes in the selected sport are eligible; every distinct event is attempted. Each matchup gets team records/injuries/history plus team leaders or players supplied by a loaded prop market. This does not mean every roster player in every sport is fetched. Progress/coverage distinguish requested, completed, matched and unavailable results. Player/stat/source failures remain visible. Broad research can increase model input costs; the full evidence stays available in the preview while AI input uses compact stat summaries for all matched games.

Research runs as an in-memory job. POST /api/research/start returns an ID; GET /api/research/status?id=... reports progress/result. Identical active slates are coalesced; two active jobs maximum, up to twelve retained, completed jobs expire after ten minutes on the next start. Reloading or restarting the server clears jobs. Preview can reconnect to an identical running slate. Ask AI previews/prepares the slate before starting generation, allowing fresh odds to be fetched after the research load. No automatic paid generation retries occur.

Adjust lines on a game loads DraftKings alternate spreads/totals through the existing odds-provider key. It is an explicit event-level call, cached 60 seconds, and consumes credits when uncached. Dropdowns show only actual returned line/price pairs. No interpolated or invented prices. Empty markets stay unavailable. Alternate quotes are removed by a full board refresh; reload them when needed. A live NFL event returned 186 alternate quotes during verification; the selected NBA event returned none, which is valid coverage.

Click a price or an AI selection to add its snapshot to Bet slip. The builder models 2–6 distinct events from DraftKings, saves locally in the browser, and distinguishes total return/net profit/break-even. It rejects same-game, mixed-book, stale and started-event illustrations. Same-game correlation/pricing, void rules and an executable sportsbook parlay price are not modeled. Re-adding a selection updates its snapshot. Saved quotes do not become current automatically.

Quote details can populate bonus-selection odds or opposing cash-hedge odds. The bonus calculator accepts an optional available-cash limit and identifies insufficient hedge cash. Free-bonus, eligibility and settlement assumptions still apply. Oregon-scoped sportsbook arbitrage checks DraftKings and user-reported ReBet when prices are loaded. Other books stay in reference mode. DFS feed prices are excluded from cash arbitrage. Matching lines still require executable prices and matching account/settlement rules.

Live all-slate validation: all eight upcoming NBA games matched, all eight summaries completed, and sixteen player overviews loaded. A seven-game synthetic regression test verifies coverage beyond the former caps, including fourteen player overviews. NFL/MLB research still depends on source identity/availability; source gaps are shown rather than described as researched.

## Underdog, PrizePicks and ReBet feeds

Based on the supplied The Odds API bookmaker documentation, native keys are `underdog` / `prizepicks` (us_dfs), `rebet` (us2, paid-subscription listing), and `williamhill_us` for Caesars (corrected from the old unsupported caesars identifier). All use the existing ODDS_API_KEY. No second odds provider is required for these connectors. Betr was not in the supplied list and remains manual-only; no invented Betr feed key is used.

Player props → Platform selects DraftKings, Underdog, PrizePicks or ReBet. Load each platform explicitly to retain labeled prices for comparison on the same event/market. Special / alternate DFS selections requests the `_alternate` market suffix for Underdog/PrizePicks. Actual market and subscription coverage varies; empty responses are not fabricated or treated as proof of a permission denial. ReBet core odds use a separate Load ReBet (paid feed) button so failures do not disable base DraftKings odds. Book-specific prop caches prevent cross-platform response reuse. Uncached requests consume provider credits.

DFS prices are indicative and can include provider-assigned defaults (e.g. PrizePicks demons/goblins). They do not encode your built entry's payout or all multipliers. Rows preserve player, stat, side, line, timestamp, platform and special-selection metadata. Price details disable cash-hedge/bonus/arbitrage/sportsbook-slip actions for indicative selections. Engines explicitly exclude DFS prices from cash calculations and best-cash-price highlighting. The manual pick’em worksheet accepts your exact gross payout table; it does not import actual entry terms or infer them from feed prices. A multi-book parlay is rejected, not modeled as an offered single-book product.

Selected DFS lines can be supplied to research and AI as comparison-only context; their indicative odds are omitted from model input. Cash bet/parlay outputs can only reference eligible sportsbook quotes. ReBet sportsbook-format quotes are supported, using the user's account-availability report and normal settlement assumptions; a price feed alone does not independently establish state licensing, currency or account entitlement.

Live validation with the configured key: one NBA player-points request returned 18 Underdog quotes and 30 PrizePicks quotes. ReBet props/core requests returned HTTP 200 with zero rows in the selected NBA check. Usable ReBet price coverage and special DFS-market availability are therefore not live-verified by those results. Fixture tests cover platform/market normalization, per-platform caches, and excluding indicative prices from cash tools. Browser checks cover comparison rows, special-market requests, disabled DFS calculator actions and ReBet board loading.

## Prop comparison, coverage and pick’em worksheet

Player props now offers Platform rows and Compare lines. Compare lines groups identical event/player/market identity and shows each loaded platform's offered lines. Standard-market line gaps are displayed only when at least two platforms each supply a single line. Special markets, mixed alternate selections and multiple lines are not summarized as a simple gap. A lower/higher line is not labeled profitable: entry multipliers, odds and settlement differ. Hide stale prices is on by default (five-minute source-update threshold); Show line gaps only is optional. Unknown/old source times can be shown by disabling the fresh filter, still marked by quote details.

Load comparison explicitly requests DraftKings, Underdog and PrizePicks (up to three uncached event requests). For special DFS markets it requests only Underdog/PrizePicks. There is no background comparison polling. Coverage cards distinguish Loading, Loaded, No prices supplied and Failed, with counts/retrieval times and safe error messages. A failed source does not discard successful feeds or substitute fabricated data. Single-platform loading remains available, including ReBet. Selected platform context for AI is kept separate from other displayed feeds.

The pick’em worksheet is manual, not an automatically verified entry quote. Copy a prop as a note from quote details, then enter the actual number of selections and ALL gross payout multipliers for each possible correct-count outcome. Gross returns include the original stake. The worksheet reports return/net per outcome and the break-even COMMON per-leg success probability under INDEPENDENCE. Optional scenario expected net uses only the user's entered common probability assumption; otherwise expected net remains absent. It never treats DFS assigned prices or historical hit rates as calibrated probabilities. Ties/reboots/voids, correlations, entry restrictions and wagering/bonus terms are not modeled. Changing leg count clears multiplier fields and requires the new table. Tables must be nondecreasing as correct count increases. Notes, entered rules and assumptions are saved locally, not synced to accounts.

Workspace persistence saves only named UI choices (sport, source, book, region, market, side, prop platform, AI sport/model). No API keys are stored. A saved Gemini model is still validated against the authenticated model catalog before generation, and Check connection refreshes available choices. Auto-refresh is intentionally not restored across restarts. Feed quotes remain server/in-memory snapshots; saved preferences do not establish current prices. Pick’em rules use a separate localStorage draft from the existing slip/watchlist.

Validation adds pure tests for line identity/gaps/freshness and full payout-table/binomial calculations, plus browser checks for batch requests, separate failures, DFS note transfer, blank probability behavior, rule resets on leg-count changes, saved model/worksheet restoration and mobile layout. No additional live provider requests or paid AI calls were needed for these frontend/calculation changes.

## Ask AI research prompts

Ask AI now uses a determined, disciplined, profit-focused research persona. Quick prompts cover strongest straight bets, deep prop research, stronger illustrative parlays, pick’em line comparisons and a skeptical slate audit. Both provider adapters share the same server instructions. Analysis must use the supplied slate, actual prices, team offense/defense and records, player season/recent stats and minutes when present, reported availability, sample scopes, source dates, contrary evidence and thesis-invalidation conditions.

This is a prompt refinement, not a new data feed or persistent player-tracking database. Missing usage/rotation/lineup/defensive-versus-position data must stay missing. Historical counts and descriptive averages cannot be promoted into calibrated win probabilities or proof of positive EV. Parlays stay distinct-event/same-book illustrations; DFS lines remain comparison-only unless exact entry terms are provided separately. Server quote validation, Out-player rejection and payout math are unchanged.
